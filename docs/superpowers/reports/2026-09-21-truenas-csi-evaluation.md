# Retained iSCSI driver evaluation — 2026-09-21

## Decision

**Do not select official truenas-csi v1.3.0 for the requested production lifecycle yet.** It fixes the REST/API direction, and its static recovery path is promising, but the released clone and incomplete-provisioning retry paths omit requested CHAP and initiator restrictions. This is a concrete implementation blocker, separate from the shared platform acceptance gaps (fencing, identity checks, format-on-blank, GitOps/credentials recovery) that also apply to the previously rehearsed democratic-csi configuration.

**Narrow next candidate:** stock democratic-csi 1.9.5 `node-manual`, if NAS allocation, snapshots, and size changes can be managed outside the CSI controller. It uses the existing portal/IQN/LUN and CHAP Secret without NAS API credentials or REST. This is a candidate for a bounded isolated rehearsal, not a production recommendation; it loses automated CSI snapshots/controller expansion. If those must remain CSI-managed, no reviewed stock candidate presently passes all requirements: await an upstream official release addressing the concrete defects. Do not build a custom CSI driver.

Read-only research only: no infrastructure access, credentials, deployment, or homelab repository edits. Public source clones are under `/tmp`. Go is unavailable (`command -v go` exited 1), so upstream tests were inspected but not executed. Findings are source-level, not observed storage incidents.

## Concrete official-driver blockers

### High: clone/restore and retry omit CHAP and initiator restrictions

Normal new iSCSI provisioning creates configured auth and initiator groups. However `createISCSITargetForClone` invokes `CreateISCSITarget`, which delegates to `CreateISCSITargetWithAuth(..., 0, 0)`. Missing auth/initiator fields are omitted from JSON. TrueNAS25.10.6 defaults missing `authmethod` to `NONE` and missing initiator to `null` (any initiator). Snapshot restore can therefore expose a clone of sensitive data without the requested target authentication/restriction. This occurs on the normal restore path, not only a rare interrupted retry. Clone extents also hardcode blocksize512 rather than preserve the requested override.

Evidence: [clone target path](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/driver/controller.go#L1472), [target helper](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/client/storage.go#L843), [JSON omitempty](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/client/storage.go#L232), [actual NAS defaults](https://github.com/truenas/middleware/blob/bf5e64c487c482617b72778b4b23b4b9e471fa16/src/middlewared/middlewared/api/v25_10_0/iscsi_target.py#L25).

`ensureISCSIChain` repeats the same zero auth/initiator call if an existing ZVOL lacks a target/extent or association; it treats any query error as missing, rather than only NotFound. Its successful retry also does not run the CHAP controller-to-node parameter bridge, so even an intact authenticated target can be returned without `iscsi.chapUsername`/`iscsi.chapPassword` after a lost CreateVolume response. [Retry path](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/driver/controller.go#L971), [bridge called only during fresh creation](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/driver/controller.go#L1106).

Source reproduction: request iSCSI clone with CHAP+initiators; trace above helper chain; emitted target group contains only portal. For partial provisioning, existing ZVOL + missing target enters the zero-auth call at995/1029. Existing tests test the CHAP helper and parameter bridge individually, not either complete path. No live exploit/reproduction attempted.

Not shown to be a new v1.3 regression: inspected [v1.0.0 clone](https://github.com/truenas/truenas-csi/blob/b29c88c4b54cafb94e3c1b138ba67fe23bae337a/pkg/driver/controller.go#L1028) and [v1.2.0 retry](https://github.com/truenas/truenas-csi/blob/5728212d097312f982ab9cd51f386416ddd558dc/pkg/driver/controller.go#L969) contain these patterns. No older safe release established.

### Important: interrupted expansion needs explicit acceptance

When native size is already at/above requested capacity, ControllerExpandVolume returns `NodeExpansionRequired:false`, even for an iSCSI filesystem. Thus NAS-growth followed by lost controller response can bypass the resizer's filesystem step. Node staging also attempts filesystem growth and may recover after remount, but this does not prove continuously mounted/rebuilt retry correctness. Node Expand can report requested capacity if connector info is missing and therefore no filesystem resize occurred. Reproduce the previously rehearsed NAS-grown/filesystem-small/full-cluster-rebuild case before any acceptance. [Controller](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/driver/controller.go#L2272), [node](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/driver/iscsi.go#L514).

### Important: mutation retries are not exactly-once

The API client automatically replays all RPC methods on connection loss, including create/delete. A lost successful mutation response may be followed by an AlreadyExists/error and cleanup, or repeated creation of resources without unique names. Subsequent CSI requests repair some resource chains, but that is not an atomic transaction. Fresh provisioning has several force/recursive rollback deletes after downstream errors. Established services must never rely on CreateVolume as recovery. Fault-inject successful mutation/lost response at each boundary. [Automatic replay](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/client/client.go#L615), [rollback paths](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/driver/controller.go#L1093).

## Static recovery, identities, writer safety — shared acceptance gaps

An official static PV uses driver `csi.truenas.io`, `volumeHandle: pool/path/to/zvol`, Retain, explicit PVC `volumeName`, and correct filesystem/access mode. Publish queries the existing dataset, finds its extent by `zvol/<dataset-path>`, targetextent association and LUN, target name and global IQN base, then publishes existing connection details. It does not call CreateVolume or allocate a replacement on the normal publish path. Missing connection metadata can produce a successful incomplete publish response, but Stage rejects absent portal/IQN. [Publish](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/driver/controller.go#L1705), [reconstruction](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/driver/driver.go#L1123).

The handle is a mutable path, not a ZFS GUID. Reconstruction does not compare captured dataset GUID, extent serial/NAA, target ID, LUN, or filesystem UUID against an external receipt. It may select the first returned association. An independent recovery gate must prove the same pool/ZVOL GUID, extent disk+serial/NAA, IQN+target+LUN+portal, filesystem UUID/type and application marker before enabling writers. Preserve records outside Kubernetes. Capture original capacities and expansion intent. Restore CHAP using exact node-side parameter names: official node code reads credentials from PV volumeContext, not CSI Secret fields. This exposes CHAP in PV attributes and is a material credential-storage tradeoff. [Node CHAP parser](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/driver/iscsi.go#L99).

Filesystem staging invokes SafeFormatAndMount. Its pinned k8s mount-utils0.34.1 treats blkid exit2 as no filesystem and runs forced mkfs for writable ext4/xfs. It does not reformat a normally recognized existing filesystem; the risk is a wrong blank LUN or unreadable/unrecognized signature. This is standard CSI initialization behavior but incompatible with an unguarded established-volume recovery. Application markers checked after mounting cannot undo formatting. No stock per-volume never-format option was found. Raw block avoids driver formatting but does not provide the filesystem PVC required by ordinary SQLite apps. [Driver stage](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/driver/iscsi.go#L176), [exact mount helper](https://github.com/kubernetes/mount-utils/blob/742616c9896fe3c0f096209413a412a3d9bffb87/mount_linux.go#L575).

RWOP is usable as Kubernetes scheduling exclusion; omission of CSI SINGLE_NODE_MULTI_WRITER capability alone is not a failure because Kubernetes CSI utilities map RWOP to SINGLE_NODE_WRITER for older drivers. Official controller publishes without tracking exclusive backend attachments; ControllerUnpublish is a no-op. NodePublish locks volume+targetPath, permitting different pod paths. RWOP does not fence a partitioned node or stop an out-of-cluster initiator. Require a power-off fencing proof and fail-closed replacement gate, plus admission preventing duplicate PV aliases, foreign bindings, dynamic established-service claims and Retain→Delete. [Capabilities](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/driver/driver.go#L704), [detach no-op](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/driver/controller.go#L1833), [RWOP fallback](https://github.com/kubernetes-csi/csi-lib-utils/blob/master/accessmodes/access_modes.go#L43).

## Exact API privileges to test, not a FULL_ADMIN assumption

The driver uses JSON-RPC WebSocket, permitting named roles on25.10.6; unlike the tested REST pairing, FULL_ADMIN is not intrinsically required. Roles are NAS-wide method privileges, not dataset-prefix authorization. A prefix is not a permission boundary.

- Startup on **controller and every node** calls pool.query → POOL_READ. Dataset query/get_instance → DATASET_READ; create/update → DATASET_WRITE; delete/rollback cleanup → separate DATASET_DELETE.
- iSCSI target/extent/targetextent query → respective SHARING_ISCSI_*_READ; create/delete → corresponding *_WRITE. Auth and initiator groups need their *_WRITE only if managed. Portal query and global.config require SHARING_ISCSI_PORTAL_READ and SHARING_ISCSI_GLOBAL_READ. Broad SHARING_ISCSI_WRITE includes more powers than necessary.
- Snapshot query → SNAPSHOT_READ; create and clone → SNAPSHOT_WRITE (clone decorator also allows DATASET_WRITE); delete → separate SNAPSHOT_DELETE. Scheduling uses SNAPSHOT_TASK_READ/WRITE.
- GetCapacity calls **zfs.resource.query → ZFS_RESOURCE_READ**, not merely pool.query.
- DeleteVolume also probes NFS shares and snapshot tasks; absent optional permissions are ignored in these cleanup paths. Grant only required features, verify actual logs.
- Startup auto-derives an NVMe portal and attempts nvmet config/query/create even on an iSCSI deployment; failures are nonfatal. Do not grant unrelated NVMe write privileges merely to silence these logs. Both node and controller chart use the same API Secret. Splitting privilege profiles needs a supported manifest configuration and explicit testing; stock chart exposes no separate node API credential setting.

Evidence: [method inventory](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/client/storage.go#L10), [startup](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/driver/driver.go#L392), [role graph](https://github.com/truenas/middleware/blob/bf5e64c487c482617b72778b4b23b4b9e471fa16/src/middlewared/middlewared/role.py#L141), [separate dataset deletion](https://github.com/truenas/middleware/blob/bf5e64c487c482617b72778b4b23b4b9e471fa16/src/middlewared/middlewared/plugins/pool_/dataset.py#L35), [snapshot roles](https://github.com/truenas/middleware/blob/bf5e64c487c482617b72778b4b23b4b9e471fa16/src/middlewared/middlewared/plugins/pool_/snapshot.py#L12), [capacity role](https://github.com/truenas/middleware/blob/bf5e64c487c482617b72778b4b23b4b9e471fa16/src/middlewared/middlewared/plugins/zfs/resource_crud.py#L136). Full live minimum-role success is **unverified**.

## NAS26 and snapshots

Official uses `/api/current` after requiring supported-version list to contain v25.10.0; it does not actually pin the wire schema to25.10. A NAS26 test must check version preflight and every used payload. It avoids REST removal, but WebSocket transport is not a compatibility guarantee. It uses `auth.login_with_api_key`, deprecated in26 and planned removed27. [API selection](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/client/apiversion.go#L108), [TrueNAS deprecations](https://www.truenas.com/docs/scale/26/gettingstarted/deprecations/).

Snapshots are native `pool.snapshot.*` with handles dataset@snapshot; restore creates a new clone identity and is distinct from reattaching retained original volumes. No application quiescing is performed, so this is storage-level consistency, not an independent database backup. Keep the externally restored application backup proof. [Snapshot code](https://github.com/truenas/truenas-csi/blob/d0cbfdceb156c774d21fb8d0b3eaf6bc9f261bb0/pkg/driver/controller.go#L1976).

## Stop/go gates

1. Official stop: CHAP/initiator-preserving clone and partial-resource retry must be fixed in a stock release and fault-injected before selection. A prior release has not solved it.
2. Shared stop: no automatic recovery writers until native identity+filesystem checks pass; no replacement while old writer might reach NAS; failed fencing must stop recovery.
3. Permission go: exact required API methods succeed with no FULL_ADMIN; unrelated datasets/resources remain at risk under global method roles and that scope must be explicitly acceptable. Or use node-manual with no NAS API credential and accept external lifecycle.
4. Recovery go: two disposable full-cluster replacements with new PV/PVC/node identities, same native GUID/serial/FSUUID, zero established-service CreateVolume, external credential restoration, intact acknowledged writes/integrity, wrong-volume and empty-volume rejection before writable mount.
5. Operational go: interrupted resize at NAS/block/filesystem boundaries, snapshot clone auth/ACL checks, outage/remount, RWOP contention, independent restore while NAS is off, and actual Argo prune/delete/resize behavior. No local lint/source review establishes rollout success.
