## Stock chart paths

Exact Operator0.94.1 source accepts custom volumeClaimTemplate names and uses them
for native container mounts. Deterministic new claims avoid deleting/rebinding the
old Prometheus/Alertmanager NFS claims. Graceful zero-writer StatefulSet replacement
handles immutable claim-template changes; ordinary reconstruction then follows Git.

Loki7.3.0 supports extra volumes/mounts and init containers, allowing the same stock
binary/config with an external static CSI claim. Its default auto-delete PVC
policy must be disabled and the existing claim protected before any scale-down.

## Tempo decision

The installed Tempo1.24.4 chart declares itself deprecated. Its complete downloaded
StatefulSet template has no init-container or startup-command extension. It can
mount an external static volume, but cannot run the retained-state startup guard.
Keeping that chart would require a fork/override or accepting an empty-state
startup risk; neither is assumed under the current design.

**Recommendation:** replace only Tempo's deployment chart with the repository's
existing `app-template`5.2.1. Keep the exact stock Tempo2.9.0 image pinned to the
currently running digest, the native configuration ConfigMap, Service,
ServiceAccount and ServiceMonitor. Continue using one StatefulSet and the same
Pod/service names, arguments, ports, probes, environment, resource budget and
service-account identity. The existing native configuration includes the same
72h retention, OTLP endpoints and Prometheus metrics-generator remote write.
Only storage, the retained-data init guard and worker placement change.

The inactive candidate renders successfully with strict chart schema validation.
A comparison verified the same command arguments/ports/probes/environment/budget,
UID10001 identity, ServiceAccount and service selectors. All four non-workload
resource objects are copied byte-equivalently from the current chart render.
The candidate retains `tempo-headless` as StatefulSet serviceName and the native
10-revision history default. It needs no CSI/application patch or new controller.
The init guard, exact native engines and recovery were subsequently qualified. The normal globals/common/app value cascade is preserved. The chart
supported enabled=false option disables the inherited placeholder `main`
container; the real `tempo` container keeps its original name, environment and
resource budget, and unused default claims are explicitly disabled. No
ApplicationSet change is needed.

The trade-off is that Tempo's native ConfigMap, Service and ServiceMonitor become
explicit repository manifests instead of being generated by its deprecated chart.
Future changes to those definitions are ordinary app-repository edits. Image
updates remain digest-pinned through Renovate and require guard qualification.

The alternative is to defer Tempo and complete the other three, preserving its
current deployment. A chart fork or an unguarded migration is not recommended.

The user approved the app-template adapter. The proposed desired source tree is
prepared locally for review; no production cutover has started.

## Completed recovery qualification

All native files and POSIX metadata were independently restored from verified
AES256 recovery media with exact stock images and no production network, scrape
targets, alert receivers or remote-write destinations. All four engines recovered
cleanly. Loki's current checkpoint and WAL recovery explicitly reported
`errors=false`; no earlier recovery exception was reused.

Prometheus: all 14 original blocks passed read-only extended promtool analysis;
15 per-block/recent-WAL queries and nine additional fixed queries matched.
Alertmanager: both retained files and the silences API matched. Its zero-byte
silences file is valid native state, so the guard requires regular files without
inventing a nonempty-state restriction.
Loki: five fixed historical queries matched after full file/metadata recovery.
Tempo: all 30 full original trace payloads matched; three complete bounded hourly
searches matched all 5,118 trace entries. First-N limited searches are nondeterministic
and are unsuitable for set equality, as documented by Tempo's native API.

The installed Prometheus Operator generated the intended custom claim names,
fixed volumeName bindings, native subpaths, read-only guard mounts and Retain
policies from zero-replica test CRs. No engine Pod, PVC or raw disk was allocated.
All temporary qualification objects, owned NAS snapshot and spool were removed,
and the original maintenance owner released. A fresh native check proved all 17
original monitoring Pod identities/readiness/restart maps and all 17 Secret
identities/types/decoded-byte hashes unchanged. Production cold-copy, physical
attachment, authority, lifecycle and rollout acceptance remain separate gates.
